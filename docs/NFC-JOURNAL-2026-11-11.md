## Retained operation and explicit recovery

`PendingTagCommit.snapshot()` returns a detached version-1 JSON snapshot containing the exact original encrypted packet (including its original nonce), authenticated section/context, expected digest/generation, original-A and previous-B pins, layout and entire original allocated baseline. Section keys are not serialized. The snapshot remains the original approved operation even after a recognized-interruption retry. `restore()` copies and validates the representation, checks packet authentication and retained pins against the original baseline, derives deterministic descriptors/write steps and compares the resulting snapshot exactly. It does not encrypt, reapprove, increment generations, create keys or start a write session.

`tests-care/nfc-commit-journal.ts` wraps that snapshot using the existing `EncryptedRecoveryDatabase` SQLite adapter. No new dependency was installed. `save(scope,id,pending,expectedHead)` must finish durably before a future caller begins transport. `restore(scope,id,sectionKey)` returns the original pending model, any completion evidence and the current journal head. The caller must obtain fresh coherent readback and explicitly reconcile or request `retryFrom(readback)`. The journal has no transport callback, background worker or device write operation. Reopening cannot replay anything.

A complete final image after a lost acknowledgement can append completion to the same retained operation. Incomplete, damaged, foreign-section or wrong-key readback cannot complete it. An explicit recognized-interruption retry retains the original ciphertext, nonce, generation, baseline and trust pins. Restoring B requires B's key and the retained trusted A pin; A's decryption key is unnecessary.

## Format, durability and conflict boundaries

- Separate explicitly initialized SQLite file, `user_version=1`, domain `matrisync-isolated-nfc-journal-v1:<store UUID>`. Creation uses exclusive file creation; reopen never creates an absent journal or resets missing/corrupt rows. Interrupted initialization may leave an unusable file which is refused, not silently repaired.
- One authenticated AES-256-GCM envelope holds a JSON map of operation, completion and head rows. It uses a fresh 12-byte storage nonce per changed transaction, a 16-byte authentication tag and the store/domain binding as associated data. This storage encryption never changes the inner approved NFC packet or its nonce. The aggregate plaintext limit is 8 MiB. All routing identifiers, baselines and evidence are encrypted; SQLite file size and filesystem metadata are not hidden.
- Reuses `journal_mode=DELETE`, `synchronous=FULL`, `BEGIN IMMEDIATE`, bounded lock retries and atomic commit. Pending operation plus head advance occur in one transaction. Completion is a separate transaction after exact full-image reconciliation and section authentication. A failure before COMMIT rolls back; a crash after COMMIT is reconciled as the original record. No per-block progress claim is persisted: fresh readback determines recognized interruption state.
- Scope is the explicit account/patient/referral triple. Patient/referral must match the packet binding. Within a scope there is one serial head spanning A and B. A new operation compares the expected head, requires immutable completion of the predecessor, matches its exact full baseline/layout, and advances only to initial B or the next B generation. A cannot be replaced. A first journal operation may be an already prepared B operation pinned to external original state; that external trust is not manufactured by the journal.
- Operation IDs are immutable within scope. Identical save retries return the original; conflicting content or parent ID refuses. Simultaneous processes with competing IDs cannot both move the same head. Historical identical retries return historical records without advancing the head. The returned restore head lets callers distinguish history from the active operation.
- Completion rows are logically append-only. They bind the original operation digest and complete final-image digest and say only `confirmed-in-model`. Exact completion retries return the same evidence, including after a later head exists; conflicting evidence cannot replace it. No device timestamp or untrusted clock is promoted to freshness. The encrypted aggregate is physically rewritten transactionally; this is not a hardware append-only log.
- Decoder rejects duplicate identities, missing links, disconnected/forked operations, cycles and missing predecessor completion. Restore also verifies completion hashes against the exact original operation/final image. Corruption and unsupported versions fail without reset or migration.

## Remaining boundaries and next slice

This is a Node/SQLite test model, excluded from public assets. Storage keys are explicitly supplied; process tests transport synthetic key bytes through private IPC. There is no production key custody, OS keystore, browser journal, account authentication, grant issuance or automatic recovery from lost keys. Caller-provided account labels enforce routing isolation, not identity authorization. Existing recovery databases and browser approvals are not migrated.

SQLite serialization protects one local journal. It does not establish exclusive physical tag ownership, prevent two devices using different databases from writing, prove readback freshness/same-tag identity, authenticate a cloned tag, or detect rollback of a complete old database with its old trusted expectations. Storage-level tampering without keys is detected; a party controlling storage keys is not a trusted authority. OS/filesystem/hardware power-loss guarantees and storage eviction are outside process-exit test evidence.

The saved completion is a local model observation, not an authenticated logger signature or authoritative latest journey. Initial B authority is still externally supplied. In-place B interruption may make old B unreadable on the tag; retaining old and pending ciphertext in the journal does not itself authorize rewriting a tag or guarantee physical recovery.

**Next:** specify and test signed logger completion, verified grants and independently trusted receiver freshness, measuring every signature, key envelope and grant byte and its transport channel. Do not treat the Section C hash or local completion as authority. Production offline provisioning and revocation remain unresolved. Only then approach a hardware driver after authorized read-only memory inspection and verified WROOM/PN532 V2.2 protocol evidence. Only 48 physical tag bytes are verified; no flash or tag overwrite was performed.
