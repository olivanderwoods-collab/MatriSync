# Clinician documentation assistance — 1 November 2026

This checkpoint follows `e31de6f`. It implements the approved source-preserving documentation workflow as a deterministic local text organizer. It is not AI extraction, clinical interpretation or completion of the three submission-core journeys.

## Working behavior

- Professional referral editors for local patients and exact received profile versions now offer “Organize supplied notes”. The clinician supplies the text, source label and optional date. Original files are not read by this helper.
- Only explicit Reason, History, Treatment and Instructions headings (including the existing full field labels) suggest placement. Unheaded text requires a manual choice. Headings, negation, units and internal whitespace remain unchanged; outer passage whitespace is trimmed. No diagnosis, medicine, urgency or destination is inferred.
- Every passage and all proposed fields are displayed before applying. Explicit review is required; changed text, source, placement or draft invalidates that review. Applying appends text to the editable draft without saving, approving or sending it. Saving remains a separate action and creates an immutable version through the existing vault workflow.
- Each appended passage includes its clinician-supplied source label and date, or “Not recorded”. These are editable attribution strings, not independently authenticated source evidence. They become part of the existing version content and approval digest and survive approved export and encrypted destination delivery.
- Existing fields, earlier versions, old approvals, original attachments and patient histories remain intact. Empty optional fields remain empty. The empty-field notice is not a clinical-completeness judgment; uncertainty detection only recognizes literal question marks and unknown/unclear/not-recorded markers.
- Inputs are bounded at 16,000 characters, 32 passages, 200 source-label characters and the existing 8,000 characters per resulting field. Invalid dates, empty recognized headings, missing placement and oversized results fail without truncating or partially applying text.
- Unsaved helper inputs are transient editor state. The local patient editor resets on patient change. Saved fields use existing encrypted records; no schema, keys, rules or external service changes were needed. RUHI's profile-only context restrictions are unchanged.
